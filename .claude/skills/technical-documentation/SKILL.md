# 기술 문서 작성 표준 (airecipe-miniapp)

이 미니앱은 백엔드(별 저장소 `AIReceipe`) 분리·TDS 의무·앱인토스 검수라는 외부 제약 때문에 결정의 "왜"를 보존하는 것이 중요하다. 문서는 코드와 함께 진화하되, 코드가 이미 말하는 "무엇"을 중복 서술하지 않는다.

## 문서 종류와 위치

| 문서 | 위치 | 목적 | 갱신 시점 |
|------|------|------|----------|
| **ADR** | `docs/adr/NNNN-title.md` | 아키텍처/패턴/제약 결정의 맥락·근거·대안 | 중요한 결정 시 |
| **포팅 사양서** | `docs/appsintoss-port/00~10` | 백엔드 호출 계약·UI 매핑·라우팅·SSE·환경 등 SSOT | 백엔드 SSOT 갱신·미니앱 결정 변경 시 |
| **AGENTS.md** | 루트 + 주요 디렉토리 | 해당 디렉토리의 역할·규약·진입점 | 모듈 구조 변경 시 |
| **README** | 루트 | 셋업·실행·디렉토리 개요 | 셋업 절차·스크립트 변경 시 |
| **코드 주석** | 인라인 | "왜"가 비자명할 때만 | 비자명한 결정 발생 시 |

> **API 문서는 본 저장소에서 작성하지 않는다.** 백엔드 API는 별 저장소(`AIReceipe`)의 `docs/api/`가 SSOT다. 본 저장소의 `docs/appsintoss-port/03-API-CONTRACT.md`가 그 사본·인용본이다.

## ADR (Architecture Decision Record)

중요한 결정마다 하나씩. 번호 순으로 누적하며 과거 ADR을 삭제하지 않는다(폐기 시 "Superseded by NNNN").

본 저장소의 ADR 번호는 **별 저장소 AIReceipe와 공유 시퀀스**다 — 백엔드 ADR-001~008 + 공통 ADR-009(포팅 결정)가 사본으로 존재하고, 미니앱 측 결정은 **ADR-010 이후**로 번호 부여 (예: ADR-010 옵션 P 마이그레이션, ADR-011 미니앱 캐싱 전략 등).

```markdown
# NNNN. {결정 제목}

- 상태: 제안됨 | 채택됨 | 폐기됨(→ NNNN)
- 날짜: YYYY-MM-DD
- 범위: 미니앱 클라이언트 | 백엔드 공통 | 양 저장소 영향

## 맥락
{어떤 문제·제약 때문에 결정이 필요한가}

## 결정
{무엇을 선택했는가}

## 근거
{왜 이 선택인가 — 디자인 패턴 선택 시 어떤 문제를 해결하는지}

## 대안
{고려했으나 버린 선택지와 이유}

## 결과
{이 결정의 트레이드오프, 후속 영향, 영향 받는 챕터}

## 참조
- 관련 ADR
- 관련 포팅 사양서 챕터 (00~10)
```

> 디자인 패턴 도입 시 ADR 필수 (`software-design-principles` 스킬). 검수 정책에 영향 있는 결정도 ADR.

## 포팅 사양서 (`docs/appsintoss-port/`)

00~10 챕터는 백엔드 저장소에서 작성된 SSOT의 사본. 본 저장소 측에서 변경할 때는:
1. 어떤 변경이 클라이언트 단독 적용인지, 백엔드 측에도 갱신이 필요한지 명시.
2. 백엔드 측 갱신이 필요하면 별 저장소의 갱신 요청을 함께 남기고 동기화 일자 기록.
3. 챕터 상단에 "마지막 동기화: YYYY-MM-DD (백엔드 저장소 commit hash)" 형식 명시 권장.

## AGENTS.md (디렉토리별)

각 주요 디렉토리(`pages/`, `src/services/`, `src/hooks/`, `src/components/`, `src/lib/zod/`)에 그 디렉토리를 다루는 사람이 알아야 할 최소 정보:
- 이 디렉토리의 책임 (한 줄)
- 핵심 규약 (예: "api-client는 단일 호출 경로", "TDS 우선")
- 진입점/주요 파일
- 주의사항 (경계면 계약·SSOT 인용 위치 등)

루트 `AGENTS.md`는 전체 아키텍처 개요 + 레이어 의존성 + 각 하위 AGENTS.md 포인터를 담는다.

## 코드 주석 정책

- 기본은 주석 없음. 잘 명명된 식별자가 "무엇"을 설명한다.
- 주석은 "왜"가 비자명할 때만 — 숨은 제약, 검수 정책 회피 결정, 토스 SDK 특수 동작, 미묘한 불변식.
- 현재 작업/이슈 번호/"X 위해 추가" 같은 휘발성 정보를 코드 주석에 넣지 않는다.
- 공개 인터페이스(api-client 메서드, 훅)에는 입출력 계약을 간결한 한 줄 docstring으로.

## 문서 유지 원칙

- 문서는 코드 변경과 같은 작업 단위에서 갱신 (코드 따로 문서 따로 금지).
- 오래되어 틀린 문서는 갱신하거나 삭제 — 틀린 문서는 없는 문서보다 나쁘다.
- 사용자 대상 설명서가 아니라 개발자/AI 에이전트 대상 기술 문서임을 기억.
- 포팅 사양서(`docs/appsintoss-port/`)와 ADR(`docs/adr/`)의 상호 참조는 양방향 링크로 유지.
